# Система управления курсами для школьников

Веб-приложение для учета школьников, образовательных программ, потоков обучения, генерации документов и массовых email-рассылок.

Система предназначена для сотрудников факультета или образовательного подразделения, которым нужно вести набор школьников на программы, управлять потоками, оформлять приказы и оперативно отправлять уведомления участникам.

## Возможности

- Ведение базы школьников с контактами ученика и родителя.
- Создание и редактирование образовательных программ.
- Создание потоков обучения с датами начала и окончания.
- Зачисление и отчисление школьников из потоков.
- Импорт школьников из Excel-файла с проверкой данных и дубликатов.
- Генерация документов в формате `.docx` по шаблонам:
  - приказ о зачислении;
  - приказ об отчислении;
  - служебная записка на оплату;
  - служебная записка на пропуск.
- Массовая email-рассылка студентам выбранного потока.
- Предпросмотр персонализированного письма перед отправкой.
- Хранение данных в PostgreSQL.
- Контейнерный запуск через Docker Compose.

## Состав Системы

Система состоит из трех основных сервисов:

- `frontend` — пользовательский интерфейс на React, раздается через Nginx.
- `backend` — REST API на FastAPI.
- `db` — база данных PostgreSQL.

Контейнеры описаны в `docker-compose.yml`.

## Технологии

- Backend: `Python 3.11`, `FastAPI`, `SQLAlchemy`, `Pydantic`, `Uvicorn`.
- Frontend: `React`, `Vite`, `Axios`, `React Router`.
- База данных: `PostgreSQL 16`.
- Документы: `python-docx`.
- Email: SMTP через стандартные библиотеки Python.
- Инфраструктура: `Docker`, `Docker Compose`, `Nginx`.

## Запуск

Для запуска требуется установленный Docker и Docker Compose.

```bash
docker compose up --build -d
```

После запуска:

- frontend: `http://localhost:3420`
- backend API: `http://localhost:3400`
- Swagger документация API: `http://localhost:3400/docs`

Данные PostgreSQL хранятся в Docker volume `postgres_data`, поэтому не удаляются при обычном перезапуске контейнеров.

## Переменные Окружения

Переменные задаются в окружении сервера или в `.env` рядом с `docker-compose.yml`.

Минимальный пример:

```env
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=university_courses
POSTGRES_HOST=db
POSTGRES_PORT=5432
DATABASE_URL=postgresql://postgres:postgres@db:5432/university_courses

VITE_API_BASE_URL=http://localhost:3400/api
```

Для серверного развертывания `VITE_API_BASE_URL` должен указывать на публичный адрес API, например:

```env
VITE_API_BASE_URL=https://example.ru/api
```

## Настройка Email-Рассылок

Рассылки используют SMTP. Для работы нужно указать параметры почтового ящика:

```env
SMTP_HOST=smtp.example.ru
SMTP_PORT=2525
SMTP_USERNAME=noreply@example.ru
SMTP_PASSWORD=mailbox_password
SMTP_FROM_EMAIL=noreply@example.ru
SMTP_FROM_NAME=Факультет компьютерных наук
SMTP_LOCAL_HOSTNAME=example.ru
SMTP_USE_TLS=true
SMTP_USE_SSL=false
```

Для SMTP через SSL обычно используется порт `465`:

```env
SMTP_PORT=465
SMTP_USE_TLS=false
SMTP_USE_SSL=true
```

`SMTP_USERNAME` и `SMTP_FROM_EMAIL` рекомендуется указывать одинаковыми. Для корректной доставки писем домен отправителя должен иметь настроенные SPF и DKIM-записи.

Важно: успешная отправка в системе означает, что SMTP-сервер принял письмо. Это не гарантирует, что письмо попадет во входящие получателя, так как принимающая почтовая система может поместить его в спам или отклонить позднее.

## Документы

Генерация документов выполняется на backend с помощью `.docx`-шаблонов. Система подставляет данные потока, курса, студентов, даты и дополнительные поля в заранее подготовленные шаблоны.

Шаблоны находятся в директории:

```text
backend/app/routers/templates
```

Поддерживаются документы:

- приказ о зачислении;
- приказ об отчислении;
- служебная записка на оплату;
- служебная записка на пропуск.

## Импорт Из Excel

Импорт школьников выполняется через интерфейс раздела студентов. Файл должен быть в формате `.xlsx` или `.xls`.

При импорте проверяются:

- заголовки таблицы;
- обязательные поля;
- корректность email;
- корректность телефонов;
- дубликаты email и телефонов.

Строки с ошибками не импортируются, а пользователь получает отчет о результатах.

## Хранение Данных

Основные сущности:

- `Student` — школьник и контактные данные;
- `Course` — образовательная программа;
- `Stream` — поток обучения;
- связь `Student` и `Stream` — зачисление школьника в поток.

Если поток удаляется, связанные с ним записи зачисления удаляются, но сами школьники остаются в базе.

Если удаляется курс, удаляются его потоки, но карточки школьников также сохраняются.

## Развертывание На Сервере

При развертывании за доменом обычно публикуются:

- frontend через порт контейнера `80`;
- backend через порт контейнера `8000`.

Внешний reverse proxy или платформа деплоя должны направлять:

- пользовательский интерфейс на frontend-сервис;
- запросы `/api` на backend-сервис.

Для frontend переменная `VITE_API_BASE_URL` применяется во время запуска контейнера через runtime-конфиг `env-config.js`, поэтому ее нужно передавать именно в окружение frontend-контейнера.

## Безопасность И Ограничения

В текущей версии основное внимание уделено учету, документам и рассылкам. Авторизация и разграничение ролей не реализованы.

Для промышленной эксплуатации рекомендуется дополнительно добавить:

- авторизацию пользователей;
- роли доступа;
- аудит действий;
- резервное копирование базы данных;
- ограничение CORS до доверенных доменов;
- историю email-рассылок;
- обработку bounce-сообщений от почтовых серверов.

## Остановка

```bash
docker compose down
```

Чтобы удалить также данные PostgreSQL:

```bash
docker compose down -v
```

Эта команда удалит volume `postgres_data`, поэтому использовать ее нужно только если данные больше не нужны.
